ROC Availability Tracker - Troubleshooting Guide

This guide will help you resolve common issues you might encounter when using the ROC Availability Tracker application. If you're experiencing problems, please try the solutions below before reaching out for further assistance.

Note: For quickest results, try using the "Load Sample Data" button instead of uploading a file. This should work even if file uploads are problematic.

Application Won't Open

Issue: The application doesn't open when clicking on index.html
Solutions:
  1. Try opening the file with a specific browser (right-click index.html → Open with → Choose Chrome or Firefox)
  2. Try running a local server:
    • Open Command Prompt or PowerShell in the l1-availability-tracker directory
    • If you have Python installed, run: python -m http.server 8000
    • Open http://localhost:8000 in your browser
  3. Check your browser's console for errors (F12 → Console tab)

CSV File Upload Errors

Issue: Getting "Error parsing CSV file: Too few fields" or similar errors
Solutions:
  1. Make sure your CSV file uses commas (,) as separators
  2. Ensure your file has the required column headers: Name, Bio, Certifications, Schedule
  3. Try using the included sample-roster.csv as a template
  4. If using Excel to create CSV files:
    • Save as "CSV (Comma delimited) (*.csv)"
    • When prompted about features not compatible with CSV, click "Yes"
  5. If fields contain commas, ensure they're enclosed in double quotes

Example of correct CSV format:

Name,Bio,Certifications,Schedule
John Smith,Network expert,"CompTIA A+, Network+",9-17
Jane Doe,Software specialist,Microsoft Certified,8-16

No Staff Showing as Available

Issue: File uploads successfully but no staff members are shown as available
Solutions:
  1. Check your Schedule format - the application supports:
    • Simple time range (e.g., 9-17 for 9 AM to 5 PM)
    • Date-specific schedules (e.g., 15/4: 9-17)
    • Day-range schedules (e.g., Monday-Friday: 9-17)
  2. Make sure the schedule includes the current time. Use the "Load Sample Data" button to see examples of correctly formatted schedules.
  3. Check the browser console (F12 → Console tab) for any error messages

JavaScript Errors

Issue: JavaScript error alerts or console errors
Solutions:
  1. Make sure all the library files are properly downloaded in the lib directory:
    • xlsx.full.min.js
    • papaparse.min.js
    • dayjs.min.js
  2. Try clearing your browser cache (Ctrl+F5 or Cmd+Shift+R)
  3. Ensure JavaScript is enabled in your browser
  4. Try a different browser (Chrome or Firefox recommended)

Data Not Being Saved

Issue: Data doesn't persist between sessions
Solutions:
  1. Make sure cookies and local storage are enabled in your browser
  2. Try using a different browser
  3. If using private/incognito mode, localStorage won't persist - try regular browsing mode

Still Having Issues?

If you're still experiencing problems after trying these solutions:

  1. Check the browser console (F12 → Console tab) for specific error messages
  2. Try using the most recent version of Chrome or Firefox
  3. Ensure all files are in the correct directory structure as outlined in the README
  4. If modifying the code, make sure syntax is correct and all files are saved properly
Remember: The "Load Sample Data" button is the most reliable way to test the application functionality without dealing with file upload issues.
